# Cidade Dorme
## Objetivos
Criar um sistema que utilize do sorteio de personagens para facilitar a partida durante o jogo Cidade Dorme, que haja espaços para escrever o nome dos participantes que ocuparão cada papel, seja ele obrigatório ou essencial; apresentar também a função de cada um dos personagens, o que ele deve fazer e as condições para sua vitória ou derrota. Também adicionar uma tela de confirmação entre o sorteio e revelação de cada papel

### Stack Tecnlógico
- Backend: PHP estruturado com sessões nativas
- Banco de dados: MySQL (PDO para segurança)
- Frontend: HTML5, PHP, CSS, Tailwind CSS

#### Regras de negócio (CORE)
Tratar senhas de usuários com hash bcript
O sistema deve ter uma página de históricos e manter sempre os logs de qualquer alteração feita por qualquer usuário, para auditorias futuras.
O software precisa de uma tela de carregamento onde terá apenas o botão de iniciar, ao apertar esse botão, o usuário entrará na parte de criar a partida, onde será possível ele adicionar os nomes dos jogadores, escolher as funções: assassino(vândalo ou silenciador), anjo, detetive, xerife, coringa, prefeito e ninja. Lembrando que a cada assassino a mais na partida será identificado como traidor, que quando o assassino for descoberto será o novo assassino, mas apenas o primeiro assassino será possívelde ter as funções vândalo ou silenciador, e cada jogador sem nenhuma função será apenas o cidadão. Também será possível escolher o número de jogadores, e escolher o modo de sorteio de funções ou do próprio usuário escolher as funções de cada jogador. A cima do ícone das funções terá uma Interrogação, que ao ser apertada abrirá uma pequena janelinha explicando como aquela função funciona. E então após a seleção do botão de iniciar partida se iniciará a parte da revelação dos papéis: aqui aparecerá na tela um papel que será rasgado por qualquer um dos cantos da tela para que os jogadores possam ver a sua função no jogo, com um pequeno texto explicativo sobre ela, e depois um botão de seta para passar ao próximo jogador, isso ocorrerá até todas as funções serem reveladas. Então depois disso entra a parte de manutenção da partida, onde o narrador terá controle: nela terá todos os nomes dos jogadores, seguido de um coração batendo para os que estiverem vivos, para quando forem assassinados o coração sangrará e vai parar de bater, um botão para revelar as funções de cada jogador e esconde-las também, para melhor organização e controle do narrador, um cronômetro que irá mostrar todo o tempo da partida, um botão que irá ativar o modo de votação onde o narrador clica nos jogadores votados e depois no mesmo botão encerra a votação e o mais votado é eliminado/morto, um botão de encerrar a partida que levará para a tela de conclusão: aqui será mostrado uma imagem que irá indicar quem venceu, o assassino, os cidadãos ou o coringa, além de mostrar o tempo de duração da partida, um botão de sinopse que ao ser pressionado mostrará número de votações que aconteceram na partida, número de assassinados,  número de pessoas salvas pelo anjo, a ordem das eliminações e todas as funções também, é claro, por fim um botão de jogar de novo, que voltará à tela de selecionar as funções mas com os mesmos jogadores da partida passada, e um botão de encerrar que apenas voltará para a tela inicial. Agora sobre a validação de regras do próprio sistema: não será possível iniciar uma partida com mais de um assassino para cada 5 jogadores, então para cada assassino, deverá ter no mínimo 5 jogadores a mais. Também terá o caso do coringa ser eliminado por votação, daí na tela do narrador aparecerá um símbolo do coringa que impossibilata o uso de qualquer outro botão da tela a não ser o de encerramento.
##### Regras Globais
- Use sempre PDO para conexão e queries no MySQL para evitar SQL Injections
- Mantenha o código limpo e comente apenas logicas complexas.
- Separe os arquivos de forma lógica: um arquivo para conexão com a base (bd.php) e scripts de backend isolados e views em HTML5/PHP, nunca faça o sistema como um monolito, deixe sempre separados todas as regras para facilitar os futuros upgrades.
 - Estilize as telas em Tailwind de forma responsiva priorizando o MobileFrist.
 - Retorne sempre as mensagens de erros de forma claras na interface para o usuário (TOAST)
 - sempre trate as mensagens de caixa de mensagens nativas do navegador em um MODAL
